## Why does a portfolio need a blog?

A portfolio shows what I built. A blog explains **how I think about a problem**, and that is what a client wants to know before hiring someone. It is also the part of the site that search engines can rank for real questions.

## Where does each article live?

Each article is a folder inside `content/blog`. The folder name is the URL, and each language is one file:

```txt title="content/blog"
how-this-blog-is-built/
  en.mdx      ← required (primary language)
  es.mdx      ← optional
  cover.jpg   ← 1200×630
```

The frontmatter holds the title, the description for search results, the dates and the key takeaways. If a field is missing or too long, the build fails and says which file and which field.

## How do crawlers read it without JavaScript?

The rest of the site is a single-page app. Google can run JavaScript, but most AI crawlers can't, so they would see an empty page.

The blog solves this at build time. After the normal build, a script renders every blog route on the server and writes one HTML file per page, with its title, canonical URL, hreflang links and structured data already inside. Vercel serves that file before the app takes over.

## What happens with languages?

English lives at `/blog` and Spanish at `/es/blog`. Each version links to the other with hreflang. If an article only exists in English, the Spanish list still shows it, marked as available in English, and links to the English URL instead of creating a copy.
